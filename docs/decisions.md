# 첫 구현의 결정을 기록한다

- 하나의 앱에 고객 접수, 사장님 관리, 공개 상태 조회를 둔다. 고객 링크는 매장 ID와 화면 종류를 지정한다.
- 초기 배포는 Sites의 소유자 전용 공간이다. AWS 자원 생성이나 실제 고객에게 공개하지 않는다.
- 서버 데이터는 D1에 저장한다. 브라우저 localStorage에는 해당 기기의 대기표 접근 토큰만 둔다.
- 매장 단위 JSON과 revision 비교 갱신으로 동시 명령의 덮어쓰기를 막는다. 전체 이력 정규화와 보관 정책은 공개 운영 전 작업이다.
- 외부 고객의 접수는 방문 확인 대기 상태다. 사장님이 확인한 순서대로 대기열에 들어간다.
- 한 명의 시술자만 지원한다. 호출 또는 시술 중인 고객은 동시에 한 명이다.
- 시술 예정 시간을 넘긴 미완료 접수는 대기 시간을 확인 중으로 표시한다. 원장이 남은 시간을 수정할 수 있다.
- 상담 고객은 최종 금액을 확인해야 완료할 수 있다. 완료 시술 합계는 실제 결제 수납액이 아니다.
- 호출은 고객 화면 안에서 조회한다. 백그라운드 문자·푸시 전송으로 표시하지 않는다.
- 네이버 연결용으로 매장 현황 링크를 만든다. 네이버 계정이나 업체 정보를 자동 수정하지 않는다.
- 초기 메뉴는 샘플이다. 사진·색상별 매장 카탈로그 업로드, 복잡한 병행 시술, 스타일 추천은 후속 작업이다.

검토에서 발견한 상담 완료 막힘, 서비스 제거 후 남은 옵션, 화면의 조합 금액 차이, 복귀 대기 순서 차이는 첫 배포 전 수정 대상으로 분류했다.
브라우저 드라이버가 없어 자동 브라우저 검증은 실행하지 않는다. 빌드와 API 검증은 화면 사용성을 증명하지 않는다.
