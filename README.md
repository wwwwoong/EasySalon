# 이지 살롱 · 소규모 미용실 운영

여러 매장의 QR 접수, 순번 호출과 운영 통계를 시험하는 첫 서버 버전입니다.

## 현재 구성

- 고객은 매장 QR에서 시술과 옵션을 고르고 방문 접수를 요청합니다.
- 사장님은 방문 확인, 호출, 시작, 완료, 보류, 취소를 처리합니다.
- 매장별 메뉴·가격·시간과 영업 상태를 설정합니다.
- 고객 대기표와 공개 혼잡도는 서버 상태를 조회합니다.
- 결제와 실제 문자 발송, 유선전화 하드웨어 연결은 포함하지 않습니다.

## 개발과 배포

Node 24, pnpm, React/Vinext, Cloudflare Worker와 D1을 사용합니다. Sites가 소스와 비공개 배포를 관리합니다.
현재 배포는 소유자 전용 테스트 공간입니다. QR에 접속할 실제 고객에게 아직 공개하지 않았습니다.
AWS 또는 미니 서버 배포를 수행한 상태는 아닙니다. 도메인과 데이터 경계를 유지하며 추후 배포 대상을 결정합니다.

프로젝트의 `package.json`과 `pnpm-lock.yaml`을 사용하여 의존성을 설치합니다.

```sh
pnpm install --frozen-lockfile
pnpm exec tsc --noEmit
pnpm run db:generate
pnpm run build
```

D1 마이그레이션은 `drizzle/`에서 관리합니다. 테이블을 요청 시 생성하지 않습니다.
호스팅 게시 과정에서 적용하며 로컬 테스트용 데이터베이스는 별도로 취급합니다.

## 첫 실행

1. 비공개 주소에 소유자 계정으로 접속합니다.
2. 샘플 매장으로 시작하여 비어 있는 담당 매장 한 곳을 만듭니다.
3. 고객 접수 화면에서 서비스와 옵션을 선택합니다.
4. 사장님 화면에서 방문 확인, 호출, 시작, 완료를 실행합니다.
5. 다른 매장 계정은 별도의 담당 매장만 관리합니다. 매장 격리는 통합 테스트로 검증합니다.

예제 메뉴와 가격은 테스트 데이터입니다. 실제 시술 가격표로 사용하기 전에 매장과 협의해야 합니다.
완료 시술 합계는 앱 기록입니다. 수납액·순이익·세무 장부를 의미하지 않습니다.
화면을 닫은 뒤의 문자나 푸시는 발송하지 않습니다. 고객 화면을 열어 둔 상태의 호출을 시험합니다.

## 공개 전 남은 확인

- 실제 두 태블릿, 안드로이드·아이폰 및 네이버 내부 브라우저의 접수 흐름을 검증합니다.
- 문자 공급사와 운영 계정, 알림 동의·보관 절차를 연결하고 실제 수신을 확인합니다.
- 네이버 매장 링크 등록을 확인합니다. 네이버 검색 결과 안에 상태를 쓰는 기능은 없습니다.
- 실제 전화 회선·장비와 수동 복구를 시험합니다.
- 실제 고객용 공개 접근과 매장 운영자 권한을 따로 검토합니다.

## 구현 원칙

pstack 참조 커밋 `5bd452955f8ded23ee81e022a19c537d6e523350`의 지침을 직접 적용했습니다.
접수 상태 전이, 요청 중복 방지, 가격 사본과 매장 격리를 테스트합니다.
출시 검증과 비공개 개발 버전을 구분합니다. 검증하지 않은 항목을 완료로 표시하지 않습니다.

메뉴 관리에서 메뉴를 추가·삭제하고 이름, 설명, 분류, 가격과 시간을 수정합니다. 저장 후 새 접수에 반영하며 기존 접수는 사본을 유지합니다. 계정당 담당 매장 한 곳만 노출하고 이전 두 번째 샘플의 데이터를 삭제하지 않습니다.

## 모드와 매출 조회

개발자 계정에는 서버 설정으로 마스터 모드를 부여합니다. 전체 매장 정보·담당 계정·공통 브랜드·공지·점검 상태를 관리할 수 있습니다. 사장님은 배정된 매장만 관리하며 일·월·기간별 완료 시술 금액을 조회합니다. 고객은 첨부 일러스트에 기반한 여성 3종·남성 2종의 머리 길이를 선택합니다. 상세 내용은 docs/modes-and-reports.md를 참고합니다.

## 매장 소개와 방문 스탬프

고객 첫 화면에 매장 이름과 소개를 표시합니다. 사장님 설정에서 이름과 여러 줄 소개를 수정합니다.
접수 시 닉네임은 선택이며, 입력하지 않으면 손님1·손님2처럼 접수 번호로 표시됩니다.

방문 스탬프는 매장별로 기본 꺼짐입니다. 사장님이 적립 목표와 혜택을 설정해 켜면, 고객이 닉네임과 적립 동의를 선택할 수 있습니다. 연결된 시술이 완료될 때 방문당 스탬프 한 개를 적립하며 취소·대기에는 적립하지 않습니다. 목표를 채운 카드는 사장님 확인 후 사용 처리합니다. 결제나 자동 할인 기능은 포함하지 않습니다.

적립카드는 매장마다 분리됩니다. 같은 닉네임도 서로 다른 카드이며, 짧은 카드 번호로 구분합니다. 고객 기기의 비밀 카드 토큰은 사장님 목록에 노출하지 않습니다. 고객은 같은 브라우저에 저장한 카드로 다시 적립할 수 있지만 닉네임만으로 복구할 수 없습니다. 브라우저 데이터 삭제와 다른 기기 이동 시 카드 복구는 현재 지원하지 않습니다.
