# 운영 인터뷰와 단계별 예약 도우미

## 현재 동작

사장님 모드 → 운영 인터뷰 · 예약 도우미에서 운영표 초안을 작성하고 확인 후 적용합니다. 직원별 가능 메뉴·근무 요일·시간, 시술 의자와 샴푸대 수, 시술별 단계와 담당자 필요 여부, 단계 소요 시간, 마지막 정리·여유 시간을 설정합니다. ‘2인 염색·커트 예시’는 명시적인 예시 불러오기이며 운영에 자동 적용되지 않습니다.

예약은 같은 담당자가 선택한 모든 메뉴를 순서대로 수행하는 모델입니다. 방치 단계는 담당자의 시간만 비우고, 설정한 자원은 계속 점유합니다. 중간 확인이 필요하면 ‘방치 → 담당자 확인 → 방치’로 나눕니다. 정리 시간은 담당자와 시술 의자를 점유합니다. 현재는 직원 최대 6명·메뉴별 최대 8단계입니다.

예약 시작 후보마다 직원의 역량·근무 구간을 확인하고, 담당자 작업 구간과 시술 의자·샴푸대 점유 구간이 겹치는지 계산합니다. 결정적인 계산기로 처리하며 고객 조회 시 AI를 호출하지 않습니다. 동시 예약은 D1의 CAS 재검사로 확정합니다. 이전 단일 예약 방식으로 확정한 예약은 전체 구간을 독점하는 것으로 보수적으로 취급합니다.

새 예약에는 담당자와 단계별 시간 배정 사본을 저장합니다. 운영표가 바뀌어도 확정 예약의 시간·담당자는 이동하지 않습니다. 직원 삭제·근무 시간 축소·시설 수 축소가 아직 끝나지 않은 확정 예약과 충돌하면 적용이나 복원을 거부합니다. 담당자의 단계 시간 변경은 이후 예약부터 적용합니다. 운영표 버전으로 오래된 승인 요청을 차단합니다.

## 현장 진행

방문 확인 후 대기표로 전환합니다. 시술 시작 시 직원·단계 사본을 연결하고, 사장님이 ‘다음 단계’를 눌러 실제 진행을 기록합니다. 방치 구간에서는 같은 담당자가 다른 고객 작업을 시작할 수 있고, 담당자가 작업 중이면 원래 고객의 담당자 작업 단계로 복귀할 수 없습니다. 샴푸대·의자 점유도 실제 현재 단계 기준으로 확인합니다. 단계 전환은 현재 단계 번호를 비교해 응답 유실 후 재요청이 다음 단계를 건너뛰지 않도록 합니다.

## 의견과 조정

버전·메뉴·단계별로 잘 맞음/빠듯함/지연/여유, 실제 소요 시간(사장님 입력), 메모를 저장합니다. 기록 기반 제안은 같은 운영 버전·단계의 시간 기록 3건 이상과 빠듯함·지연 의견 2건 이상이 있어야 하며 중앙값을 근거로 한 번에 최대 5분 늘립니다. 한 번의 경험으로 자동 변경하거나 시간을 자동 단축하지 않습니다. 제안은 별도 승인 전까지 운영에 영향을 주지 않습니다. 최근 10개 이전 운영표를 보관하고 복원 시에도 기존 확정 예약과 충돌을 검사합니다.

## 선택적 AI 연결

현재 배포에는 AI 키가 없으므로 화면은 ‘AI 분석 연결 준비 중’입니다. 운영표 직접 입력, 직원/단계 계산, 사장님 의견, 기록 기반 제안은 AI 연결 없이 동작합니다. 이를 실제 AI 분석으로 표시하지 않습니다.

서버 런타임에 비밀 값 `SCHEDULER_AI_KEY`와 사용할 모델 ID `SCHEDULER_AI_MODEL`을 설정하면 ‘AI로 인터뷰·의견 분석’ 버튼이 활성화됩니다. 모델은 Responses API와 엄격한 Structured Outputs를 지원해야 합니다. 키를 소스·클라이언트·GitHub에 넣지 않습니다. 담당 매장 사장님·마스터만 온디맨드 분석할 수 있고 매장별 1분 호출 간격과 30초 응답 제한을 적용합니다.

AI는 인터뷰와 운영 정의·최근 의견을 입력받아 운영표 초안·설명·추가 질문을 반환합니다. 예약 고객 실명·전화번호·토큰 및 예약 목록은 보내지 않습니다. 자유 텍스트의 휴대전화·이메일 형식을 가리고 직원 표시는 역할명으로 대체합니다. 자유 입력의 모든 개인정보를 자동 검출하는 것은 아니므로 고객 개인정보를 입력하지 않도록 안내합니다. `store:false`로 요청하며 반환값은 서버 기준으로 재검증하고 초안에만 저장합니다. 분석 도중 매장 상태가 달라지면 결과를 덮어쓰지 않습니다. 실제 외부 AI 호출은 키 미설정으로 검증하지 않았으며 테스트는 모의 응답을 사용합니다.

구현 참고: https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses

## 한계

- 휴게시간, 특정 날짜 휴무, 보조 직원으로의 단계별 인계, 고객의 특정 디자이너 선택은 아직 지원하지 않습니다.
- 예약 가능 시간 계산은 확정 예약과 운영표 기준입니다. 방문 접수·현장 지연을 미래 예약에 자동 전파하거나 예약을 재배치하지 않습니다.
- 사장님이 단계를 직접 전환합니다. 단계별 자동 타이머 완료·문자 알림·자동 시간 단축은 없습니다.
- 기존 공개 대기 예상은 보수적인 합계이며, 직원별 단계 진행을 반영한 정밀 예측은 별도 확장 항목입니다.
- 브라우저·실제 모바일 UI 검증은 아직 수행하지 않았습니다.
